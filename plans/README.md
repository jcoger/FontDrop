### Dependency notes
- **001 is a soft prerequisite for 002** (and nice-to-have before 006): its characterization tests are the safety net that makes the scoring/DB changes provably non-breaking. 002 is *expected* to flip some 001 tests — the executor of 002 re-pins them; that's the net working.
- **003 and 006 are complementary, not ordered:** 003 makes a schema-drift read fail gracefully; 006 removes the drift at the source. Either order; both worth doing. 006 is the highest-risk plan (runs at every startup against real user data) — do its real-DB smoke test.
- **Phase 3 (004, 005, 007) is fully independent** of the backend phases and of each other. These can be parallelized or interleaved freely.
- **No plan depends on another's code changes to compile** — the ordering is about leverage and safety, not hard build dependencies.

### Suggested execution batches
- **Batch A (backend session):** 001 → 003 → 006 → 002. Coherent — all Rust, test-guarded, one `cargo test` loop.
- **Batch B (frontend session):** 004 → 005 → 007. Coherent — all `tsc`/app-verified, no Rust rebuild.

You can run `/improve execute <plan>` on each in turn (dispatches an executor in an isolated worktree, then I review the diff), or hand the files to another agent.

## Considered and rejected / deferred

From the pairing audit:
- **Superfamily prefix over-matching** (`metrics.rs` Pass-3) — real but bounded; deferred pending a decision on keeping name-prefix inference.
- **Weight-range consolidation runs every startup** (`db.rs:310`) — idempotent, low impact; deferred.
- **Plaintext Google API key** (`google_fonts.rs:115`) — user's own key, local-only app; low severity. Deferred (a code comment is the most warranted).
- **`refresh_google_fonts` u32 underflow** (`db.rs:588`) — edge case; fold into a future robustness pass.

From the product audit (false positives / not worth a plan):
- **"Stale `starred.toggle` in keydown handler"** — REJECTED: `toggle` uses a functional `setStarred(prev => …)` with empty deps ([useStarred.ts:47](../src/hooks/useStarred.ts:47)); it is stable and never stale.
- **"3–4s freeze on large extraction image"** — REJECTED: the extraction canvas is hardcoded 200×200; work is bounded (~100ms), not seconds. (Captured accurately in plan 005.)
- **"Google API key exposed to frontend"** — DOWNGRADED: `get_google_api_key`/`set_google_api_key` are never called from the frontend (dead surface, folded conceptually into the dead-code cleanup), not a live exposure.
- **CSP disabled (`tauri.conf.json` `"csp": null`)** — DEFERRED: low risk for a local app with a correctly-narrowed asset scope; free hardening for a later security pass.
- **Triplicated contrast helpers** (`hueLogic`/`mkLogic`/`wpLogic`) — real DRY issue (confirmed 3 copies, `mkLogic` already drifted with an extra `fgBias` param); deferred as a focused ColorExplorer refactor, not batched here.
- **App.tsx size / ColorExplorer monolith / prop-drilling** — architecture observations, not rushed: large but coherent; revisit when next extending those areas.
- **`bloom-menu ^0.1.0` alpha dep**, **README missing dev/build section**, **symlink cycle guard in font scan**, **`ColorSwatch` blur stale-prop (low confidence)** — minor; deferred.
